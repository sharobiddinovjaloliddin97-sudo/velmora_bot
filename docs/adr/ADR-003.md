# ADR-003: Service Layer Pattern

## Status

Accepted

## Decision

Business logic will be implemented in service classes instead of serializers or views.

## Context

As the application grows, user registration, authentication, loyalty, vouchers, notifications, and integrations will require complex workflows. Placing this logic inside serializers or views would make them difficult to maintain.

## Decision

Introduce a service layer for each domain. Serializers are responsible for validation and data transformation. Views handle HTTP requests and responses. Services implement business rules and coordinate interactions with models and external systems.

## Consequences

- Business logic is reusable across API views, management commands, and background jobs.
- Serializers remain focused on validation.
- Views remain focused on HTTP concerns.
- Database transactions can be managed centrally within services.

## Applied To

- User registration
- User authentication (login)
